STAMPED: principles for reproducible research

Self-contained
Reach all essential components from one project root.
Tracked
Record which versions produced each result.
Actionable
Provide executable procedures and reproduction instructions.
Modular
Separate components for reuse and recombination.
Portable
Specify dependencies and required computing environments.
Ephemeral
Use a disposable environment for each execution.
Distributable
Preserve retrievable components and rebuildable environments.

01 · Experiment

Improve the skills
by testing their results

We wished to iteratively improve skills for STAMPED research by validating the scientific results and research objects they produced.

Do successive revisions improve scientific adequacy, reproducibility and consistency?

  1. RunFresh agents address the same scientific question.
  2. AssessIndependent judges inspect the research object and attempt replay.
  3. ReviseUse recurring findings to improve and compress the skills.
  4. RepeatTest the next pinned revision with fresh agents.

Three iterations of testing and revision. In the final iteration, evaluate without further tuning.

The study is itself a research object

Follow any result back to its source

Versioned inputs↓ Task + skill revision + environment↓ Code + execution records + results↓ Assessments + reasons for revisions

stamped-in-practice links the skills, data, runs, assessments and revisions—including unsuccessful attempts.

This lets others assess both the scientific results and the process of improving the skills. Ideas for better guidance become testable when we can trace the data generated along the way.

Put the principles to work

The skills guide project creation, analysis, assessment and improvement. They make STAMPED actionable guidance for an agent.

Use the STAMPED checklist to examine your own research object, then follow the evidence behind each answer.
