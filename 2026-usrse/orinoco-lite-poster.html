Who works on which project, and what has it produced? Labs repeatedly assemble these facts for websites, grants and reports. ORINOCO makes them a shared collection of structured, connected records that people, software and AI tools can use.

Deploy with dedicated services, or use our GitHub-based model with no services for your lab to deploy.We compare two ways to run the same metadata approach: the service deployment at Psychoinformatics and ORINOCO Lite at the Center for Open Neuroscience (CON).

1 · Dedicated services

ORINOCO

Developed by Michael Hanke and colleagues at Psychoinformatics, INM-7, Forschungszentrum Jülich, ORINOCO connects open tools for research information. A metadata service accepts submissions from people and software; curation tools turn them into a reusable collection.

A schema defines record types, fields and relationships, such as a person’s role in a project. The same definition generates editing forms and checks whether submitted records have the expected structure.

The Psychoinformatics website is one view of this information.
psychoinformatics.de

How a change becomes reusable data

A person editsSHACL Vue presents a form derived from the schema.
A tool submitsAn automated process prepares structured records.

Both submit records ↓

  1. Validate and stageThe Dump Things Service checks incoming records against the schema and holds submissions separately from the curated collection.
  2. Review the submissionCurators inspect, modify, accept or reject submissions using tools outside the storage service. Curation can be performed by people or automated processes.
  3. Update the collectionAccepted records are promoted into the service’s curated collection, where identifiers connect people, projects, publications and other entities.
  4. Query and presentquery-things selects and joins records. www-from-model supplies page templates and the graph generator; Hugo renders the website. Other consumers can generate reports or catalogs.

Services connect the tools

For ORINOCO, developed and used by the Psychoinformatics group, Forgejo provides identity, access and website workflows. Dump Things supplies the metadata API and storage. Lab-in-a-Box deploys these components alongside other lab services.

2 · GitHub-based deployment

ORINOCO Lite at CON

Developed and used by CON, ORINOCO Lite keeps ORINOCO’s schemas, editor and processing tools, while placing records in Git and review in GitHub pull requests. A reusable package and repository template bring these components together for a static website.

The repository becomes the group’s official metadata collection. Records are readable text files with a change history. GitHub Actions runs validation and publication, so the lab maintains its information without operating a metadata server.

The CON development website uses the GitHub deployment.
dev.centerforopenneuroscience.org

How a change becomes reusable data

A person editsThe static /edit/ page opens a pull request from a SHACL Vue form.
A tool proposesAn adapter workflow opens a pull request; /review/ records which proposals to keep.

Both produce a pull request ↓

  1. Validate and stageGitHub Actions converts the submitted edits or selected proposals into schema-validated metadata changes in the pull request.
  2. Review the changesGitHub shows the proposed record changes for discussion and approval. Adapters can draw on existing sources, such as the lab’s Zotero publication library.
  3. Update the collectionMerging the pull request updates the YAML records on the repository’s default branch. Git retains the accepted changes and their attribution.
  4. Query and presentActions selects and joins records using the same www-from-model templates and graph generator. Hugo renders the site for GitHub Pages; the source records remain in Git.

GitHub connects the tools

For ORINOCO Lite, developed and used by CON, a shared GitHub App handles sign-in and GitHub operations for browser editing and review. It stores no metadata and is outside the build and public reading paths.

Lab-managed inputs: records, site content and configuration. Separately maintained components are pinned with submodules; large media can use git-annex.

3 · Local use, global connections

Useful in the lab.
Connected beyond it.

Both deployments serve the same purpose: maintain information where a group knows it best, and describe it in ways that other tools and organizations can understand.

Within a group: collect once, reuse

Link people, projects, publications and datasets. Validation checks the structure; explicit relationships let websites, reports and queries reuse the same records instead of maintaining separate lists.

CON’s graph explorer: the relationships behind pages, related-item lists and cross-links.

Across groups: shared meaning

Ontologies give concepts and relationships shared definitions. Mapping local records to these terms makes them linkable to independently maintained research information.

ORCID identifies people; DOI identifies publications. schema.org supplies a shared term for names; W3C PROV supplies one for roles.

For AI-assisted work, explicit fields, identifiers and relationships provide context that tools can query, validate and update without having to infer the data model from scattered prose.

Already beyond the website: the upstream TRR379 deployment uses its central metadata infrastructure to collect personnel information and generate a DFG annual-survey PDF.

One vision, two operating models

Regardless of how it is deployed, ORINOCO connects a global approach to describing research with tools a small organization can use and maintain locally.

A website is an immediate use; the enduring resource is structured knowledge, ready for new questions and applications.
